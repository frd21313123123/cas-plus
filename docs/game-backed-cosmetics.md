# Game-backed cosmetics catalog

`cas+` now builds its cosmetic catalog from the user's installed CS2 immediately before the payload is injected.

The loader reads the installed `csgo/pak01_dir.vpk`/loose game files, parses `scripts/items/items_game.txt`, resolves localized names from the installed game resource file, and derives weapon/paint compatibility from `alternate_icons2`. It records the real item definition, paint kit, localized weapon/finish names, Panorama icon resource path, and player/world model paths.

Records are deduplicated by `(item definition, paint kit)`. The payload rejects arbitrary raw paint IDs. An obsolete stored combination is preserved on disk, labelled as unverified in My items, and not projected into the client until the user replaces it with a verified finish; catalog loading never silently rewrites user inventory.

The generated snapshot is versioned and checksummed at `%TEMP%/cas_plus_game_catalog_v2.bin`. It is bound to the target process ID and creation time, then regenerated by the loader before injection, so an old or partial snapshot is rejected rather than reused for another game process.

The current GDI menu consumes game-backed names and compatibility data. `iconResource` is the exact game Panorama/compiled-resource path. Source 2 `.vtex_c` pixel decoding is not implemented, so the selector deliberately shows a neutral text preview instead of synthesizing artwork or rarity.
